# 文种判断

必须先判断行文关系、是否要求批准、是否对社会公开，再判断内容主题。不得只凭标题末尾一个词决定文种。

| 场景证据 | 文种 | 输出值 | 纪律 |
| --- | --- | --- | --- |
| 请求有隶属关系的上级批准或答复一个事项 | 请示 | `request` | 一文一事，不夹带工作汇报；必须有明确请示事项 |
| 向下级或有关单位发布执行安排、任免或转发事项 | 通知 | `notice` | 写明对象、任务、时限、责任和反馈路径 |
| 向上级汇报工作、反映情况、回复询问且不要求批准 | 报告 | `report` | 不得在结尾夹带“请批准”事项 |
| 不相隶属机关之间商洽、询问、答复或请求支持 | 函 | `letter` | 行文语气平等克制，事项和回复要求明确 |
| 记载会议基本情况和议定事项 | 纪要 | `minutes` | 只记会议形成的意见，不补造讨论过程 |
| 对一个阶段工作复盘、归纳经验并安排后续 | 总结 | `summary` | 区分已完成事实、问题判断和下一步安排 |
| 对重要事项作出决策部署、奖惩或变更 | 决定 | `decision` | 决定事项必须具有权限依据和执行边界 |
| 向国内外宣布重要事项或法定事项 | 公告 | `announcement` | 面向社会公开，发布范围高于一般通告 |
| 集中发布法规、规章、决定、命令等正式文件 | 公报 | `regulation` | 用于权威汇编发布，不等同规章文本本身 |
| 在一定范围公布应当遵守或周知的事项 | 通告 | `proclamation` | 明确适用地域、人群、期限和法律后果 |
| 上级答复下级请示事项 | 批复 | `reply` | 引述来文，明确同意与否及办理边界 |
| 依照法定权限公布行政法规、宣布施行重大强制措施等 | 命令 | `instruction` | 仅法定主体使用，必须有命令号、签署人和日期 |
| 各级人民政府按程序提请同级人大或常委会审议事项 | 议案 | `proposal` | 写明法定主体、案由、议案内容和审议请求 |
| 对专项工作预先设计目标、任务、进度和保障 | 工作方案 | `work_plan` | 必须可执行，不得只有原则性表态 |
| 面向特定对象汇报职责履行、成效、问题和打算 | 工作汇报 | `work_report` | 非法定文种；若正式上行且无需批准优先判报告 |
| 内部快速反映动态、经验、问题或工作信息 | 简报 | `briefing` | 信息短、事实密，不作无依据的普遍结论 |
| 领导在部署、动员、总结等场合作完整讲话 | 讲话稿 | `speech` | 体现讲话人职责和现场对象，兼顾口语节奏 |
| 会议交流、表态、研讨或代表发言 | 发言稿 | `presentation` | 聚焦一个主题，篇幅和身份边界小于讲话稿 |
| 参与方记录已确认事项、共识和后续安排 | 备忘录 | `memo` | 不把未确认事项写成协议结果 |
| 邀请特定对象参加活动、会议或访问 | 邀请函 | `invitation` | 时间地点、活动安排、回执方式必须明确 |
| 机关或单位证明某个可核验事实 | 证明 | `certificate` | 只证明权限和材料范围内事实，不作评价担保 |
| 材料不足或确实不属于以上类型 | 其他 | `other` | 输出候选类型与缺失信息，不强行套用文种 |

易混边界：

- “请示”要求上级批准；“报告”只汇报，不请求批准。
- “批复”是上级对下级请示的答复；平行单位答复使用“函”。
- “公告”宣布重要或法定事项；“通告”公布一定范围内应遵守或周知事项；“通知”通常有明确组织执行对象。
- “工作汇报”“工作方案”“简报”是事务文书；正式法定行文时，应优先判断是否属于报告、通知等法定文种。
- “讲话稿”通常代表领导作完整部署；“发言稿”通常用于交流、表态或短时发言。

证据不足时降低 `confidence`，在 `alternatives` 给出不超过 3 个候选，并在 `missingInformation` 写明需要用户补充的行文关系、预期动作或发布范围。不得自行补造这些信息。
